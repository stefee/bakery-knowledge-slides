Grounding an AI agent with Google's Open Knowledge Format

Hearth & Wheel Bakery · a fictional bakery, a real experiment

Two-day hackathon. One question: does OKF actually work for grounding an agent in business-specific context?

The problem

Every business has its own vocabulary.

  • Internal jargon no model has ever seen
  • Ordinary words with special meanings
  • Terms that only make sense in relation to each other

An ungrounded agent will guess, ask, or confidently hallucinate.

The question

Is a folder of markdown files enough to ground an agent in business context and terminology?

Open Knowledge Format (OKF): markdown + YAML frontmatter, no registry, no required tooling.

What is OKF?

  • Readable by humans without tooling
  • Parseable by agents without bespoke SDKs
  • Diffable in version control
  • Portable across tools and orgs

The real payload: relationships

Business context isn't a glossary. It's a network of dependencies.

Kettle Process→ Ember Index→ The Wheel→ Michael
  • Badly proved dough bakes unevenly and the Ember Index spikes
  • Nightwatch logs the Index; an alert usually means a spike
  • A poor Index can force the day's Wheel to be reshuffled
  • Michael can tell a cafe whether their delivery moved

The experiment

Two Claude Code sessions, identical except for one thing.

Without

Vanilla Claude Code

No knowledge, no MCP servers

With

Claude Code + knowledge MCP server

Plus a short "look up company terms, don't guess" hint in CLAUDE.md

Any correct answer in with can only have come from the knowledge base.

Keeping the test honest

If the agent could just read the files off disk, the demo proves nothing.

  • Sandboxed sessions in a neutrally named workspace outside the repo
  • Deny rules for the parent directory, so repo names don't leak
  • Generated config kept outside the repo; no repo-derived env vars
  • Only with gets the MCP server; it must go through the tools

Several leak vectors found and closed along the way: cwd, git status, parent CLAUDE.md, settings paths, ~/.claude.json.

What we learned

  • Availability isn't use. Given the tools, the agent answered "What is Looming?" without consulting them. A short CLAUDE.md nudge fixed it.
  • The nudge must be short and free of domain terms, or the test stops being fair.
  • Unknown terms: with the hint, the agent said "not found" rather than inventing an answer.
  • Isolation is the hard part: proving where an answer came from takes real effort.

What's next

  • Human review: add verified and sources to concepts (currently all generated)
  • Try a real internal domain instead of a fictional bakery
  • Measure answer quality across more prompts and models
  • Keep bundles fresh as agents maintain them
